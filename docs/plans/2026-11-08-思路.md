# sborganize 思路纪要

**日期：** 2026-11-08\
**对应英文设计：** [2026-11-08-sborganize-design.md](./2026-11-08-sborganize-design.md)

## 要解决什么

参考 [iphone-home-screen-organizer](https://github.com/lunkerchen/iphone-home-screen-organizer)：用 USB 读主屏 → AI/规则整理 → 压缩 → 稽核。能力在，但体验碎、默认容易上云、写路径绑在 Unjiggle 上。

我们要：**更好用、更直觉、更简洁、privacy first**；尽量本地智能；开源 GitHub CLI，不做品牌 App。

## 关键取舍

1. **读写自研** — 直接用 `pymobiledevice3` 操作 SpringBoard `IconState`，不包一层 Unjiggle。差异化放在规划、安全与体验。
2. **Python** — 设备协议生态成熟，CLI 迭代快。
3. **规则为主 + 本地模型为辅** — 默认离线规则（钉住 Dock、归入已有文件夹、少建新夹、压缩空页）。`--smart` 时：Apple 本机 → Ollama → 退回规则。不做云端 LLM。
4. **默认只预览** — `plan` 不写机；`apply` 才写，且强制 backup + round-trip + 确认。
5. **无产品名包装** — 仓库/命令就叫 `sborganize`（SpringBoard organize）。

## 体验原则

- 命令少：`demo` / `doctor` / `scan` / `score` / `plan` / `apply` / `restore`
- 输出北欧极简：少装饰、状态色克制、diff 用短动词
- 两分钟能看懂隐私承诺（见 `PRIVACY.md`）

## 明确不做（v1）

- 品牌 GUI / App Store 上架
- 卸载 App、自动删应用
- 云端模型后端
- 保证 iOS 写回后布局永不回流（只保证可备份、可恢复、读回校验）

## 落地顺序

见 [implementation plan](./2026-11-08-implementation-plan.md)：先 fixture/`demo` → 规则 `plan` → 真机 `scan` → 安全门后的 `apply` → 最后才接 `--smart`。
