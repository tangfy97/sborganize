# Public CLI alpha

The owner is satisfied with the organized phone and has made manual refinements.
This release work must not read or write that device. It prepares the existing
open-source CLI for other users, without a frontend or paid model calls.

## User journey

1. Install from a tagged GitHub release and run a bundled, unsaved offline demo.
2. Discover commands through a short welcome, grouped help and local guides.
3. Connect a trusted phone, inspect it and preview a conservative rules plan.
4. Inspect the saved target and full details without another device read.
5. Apply only with confirmation, verified backup, unchanged round-trip and readback.
6. Find local backups and understand failure recovery from focused documentation.

Whole-layout emoji policies and optional cloud advice remain separate advanced
workflows. Exported policies enumerate every app but require deliberate human
classification. No implicit cloud fallback is introduced.

## Terminal contract

Use restrained color and compact destination-oriented previews. Show every
position on demand and before a write. Treat app names as literal text, remove
terminal control escapes, respect NO_COLOR and keep JSON undecorated. Offline
inspection must not depend on a phone, key, network or model assets.

The most recently generated valid plan is selected consistently across rules,
review conversion and policy modes. Saving a synthetic demo is explicit; it is
best rehearsed in a separate data root.

## Release evidence

Use synthetic fixtures and fake devices for tests. Build a wheel and source
archive, inspect their contents, install the wheel into a fresh environment and
exercise the complete offline workflow outside the checkout. Publish only public
source and documentation: never local dumps, private policies, keys or backups.
Run Linux/macOS CI before tagging the GitHub prerelease. Hardware writes remain
experimental and hardware restore remains unvalidated.
