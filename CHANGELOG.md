# Changelog

## 0.1.0a10 — 2026-11-09 · first public alpha

- Added a short welcome, grouped help, restrained terminal color, plain/NO_COLOR
  handling, literal app labels and compact grouping previews with full detail on demand.
- Added bundled offline guides, portable demo saving, saved target inspection,
  private configuration initialization, effective config display and backup browsing.
- Fixed plan selection across rules, review and policy modes, so apply uses the
  newest generated plan rather than an older latest.json. Added safe local pointers.
- Added policy draft/source export with exhaustive app membership and explicit
  unresolved destinations, plus improved USB-permission errors and write-stage UI.
- Added English/Chinese entry guides, focused reference/recovery documentation,
  synthetic terminal artwork, pinned CI, clean-wheel smoke checks and release hashes.
- No real phone edits or paid model requests are required for this release work.

## 0.1.0a9 — 2026-11-09

- Added explicit, offline `plan --policy`: exhaustive per-app destinations and
  reasons, emoji-only names, declared folder renames/order, adjacency checks and
  sequentially filled folder pages. Reuses every existing editable folder/slot.
- Preserved normal-mode restrictions. Serialized folder edits whitelist only each
  source folder's target position and display name; other metadata, app payloads,
  dock, pins and opaque nodes remain strict throughout planning and apply.
- Added a per-app audit, fixture apply coverage and default-mode regression checks.
- Persisted the user's revised domain-first banking/bills exceptions, separate
  AI and entertainment, shared learning/cloud group and finer transport split in
  a private device policy. No new cloud request is required.

## 0.1.0a8 — 2026-11-09

- Removed newly empty trailing pages from edited folders during regrouping.
  iOS drops these on write; predicting them caused a false strict read-back mismatch.
  Untouched folder payloads and all unknown-node comparisons remain strict.
- Added regressions for widget-field loss and app additions during the unchanged
  round-trip: both must stop before writing the target and retain the backup.
- First authorized hardware target write completed on 248 apps, reducing four
  pages to three. Its immediate readback matches after the planner correction.
  Later layout changes were observed and are recorded separately, without further
  writes or automatic rollback. Hardware restore remains unvalidated.

## 0.1.0a7 — 2026-11-09

- Rechecked live review quality: schema-complete responses can still misidentify
  apps, infer regions from publisher origin or propose incompatible folder domains.
  Added identity/domain checks and independent-evidence requirements for regional claims.
- Preserved original model candidates for local `review --recheck`, with no key or inference.
- Added `plan --from-review` to produce a separate regrouping preview. Explicit
  local category/folder maps take precedence, including user-requested prototype groups.
  Dock, pins and unknown nodes remain fixed; emptying an existing folder is refused.
- Added strict additive device refresh: only appended recognized icons and known
  app bookkeeping changes can reuse prior advice. New icons use explicit local
  rules or stay loose; they are not claimed as model-reviewed.
- Added CZ health-insurance / GoPay finance identity rules and service-region
  corrections. No actual hardware write success is claimed.

## 0.1.0a6 — 2026-11-09

- Replaced cloud review arrays with required app-ID keys in the requested schema;
  kept validation support for well-formed legacy arrays. Rejected duplicate JSON keys.
- Aligned schema and prompts on nonempty domain/reason fields and explicit unknown
  values. No invalid result is promoted to a recommendation.
- Added private field-level diagnostics for rejected batches and concise incomplete
  coverage output, with the full unreviewed inventory retained in the JSON report.
- The first whole-inventory live run failed batch validation at 0/244. Its response
  was not retained, so the exact historical cause remains unknown; the new response
  contract and diagnostics are verified with synthetic HTTP responses.

## 0.1.0a5 — 2026-11-09

- Added whole-inventory `review`, including apps already in folders, dock and pins.
  Offline rules remain default; `review --cloud` explicitly shares all app names/IDs
  and current folder membership with OpenRouter. No local model is probed.
- Saved advisory reports separately from apply plans, with per-app reasons,
  region/domain checks, folder summaries and explicit incomplete coverage.
- Added bounded cloud batches, private resumable caches and `--from-plan` snapshots.
  Failed or malformed batches are not cached; completed cache-only runs need no key.
- Improved unresolved-plan rejection diagnostics and bounded model explanations.
  Earlier rejected suggestions do not prove the model intentionally abstained.

## 0.1.0a4 — 2026-11-08

- Added a native Apple Foundation Models CLI bridge, availability diagnostics and
  schema-guided refinement for unresolved apps. Apple failure retains rules.
- Added separately opted-in OpenRouter refinement (`--cloud`), using a locally
  supplied environment key or hidden ephemeral terminal input, with minimized metadata. This changes the original
  no-cloud scope only for explicit cloud runs; see PRIVACY.md. Default and Apple
  modes never fall back to cloud. Ollama is excluded at the user's request.
- Added guarded experimental USB apply/restore, verified raw backups, stale-plan
  checks, confirmation before the unchanged round-trip and strict read-back.
- Added device-ready XML plist preparation; loose slots compact only after fixed
  anchors, with every move in the preview. Unsupported anchored gaps refuse.
- Post-write verification tolerates only known app bookkeeping changes; unknown
  payloads remain strict. Actual hardware write validation is tracked separately.

## 0.1.0a3 — 2026-11-08

- Added grouping percentages for existing-only plans, explicit metric scope and
  finer transport/trip peer matching.
